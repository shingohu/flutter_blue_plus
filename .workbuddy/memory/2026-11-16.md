## 重命名 openPermission → openPermissionSetting(跨端 breaking change)
- 用户要求改名。涉及 4 层,必须全链路同步,共 10 文件 34 处:

- 根目录 `README.md` 是软链接 → `packages/flutter_blue_plus/README.md`,改主包 README 即自动同步,不要重复编辑。

## 四个权限方法接入已有 _invokePlatform 桥
- 关键事实:`flutter_blue_plus.dart` **本就有** `static Future<T> _invokePlatform<T>(Future<T> Function() invoke)`(文件末尾 ~701 行),内部先 `_initFlutterBluePlus()` 再 invoke,全项目所有平台调用都走它。
- 四个权限/适配器方法原本直接调 `FlutterBluePlusPermission.instance.xxx()`,**绕过了初始化**。本次改为 `_invokePlatform(() => FlutterBluePlusPermission.instance.xxx())`,T 推断为 bool,复用桥接。
- 踩坑:一开始误以为没有该 helper,新增了一个 `static Future<bool> _invokePlatform(Future<bool> Function())`,造成 duplicate_definition 且遮蔽泛型版本,导致 getPhySupport/bondedDevices 等全部类型报错。正确做法是先 grep 全文件确认 helper 是否已存在。删除误加定义后 analyze 恢复(仅 8 个既有警告)。

## 评审用户手改的 isBluetoothAdapterOn(已修回纯转发)
- 用户把该方法改成 `_invokePlatform((){ if (adapterStateNow == unknown) { await adapterState.where((v) => v == on).first; } return isBluetoothAdapterEnable; })`。评审结论:**不可用**,已修回纯转发。
- 三个问题:① 闭包不是 `async` 却用 `await` → `await_in_wrong_context`(analyze 实测 line 190);② `.where(v == on).first` 只在蓝牙打开时才完成,蓝牙是 off 时**永久挂起**,与 doc "Returns false when off" 矛盾;③ 最终返回值来自 permission 包的独立 channel 查询,与 `adapterState` 缓存无关,等流纯多余,还多一次 `getAdapterState` 平台调用。
- 附带:订阅 `adapterState` 会走 `FlutterBluePlusPlatform.instance` 通道,而 `permission_api_test.dart` 只 mock 了 `flutter_blue_plus_permission` 通道 → 该测试会挂住。
- 事实依据:`adapterState` 是 `async*` getter(line 294),缓存为 null 时内部已自行调 `_invokePlatform(getAdapterState)` 拉取状态,并用 `newStreamWithInitialValue` 立即 yield 初始值;不需要外部再等。
- 若日后确实要"状态未知时先同步缓存",正确写法是 `await adapterState.first`(取首个真实状态,on/off 都算)并补平台通道 mock,且必须加超时/防挂死。当前无此需求。
- 修复后 `flutter analyze` 仅剩 8 个既有 `invalid_dependency` 警告。所有改动仍未提交未推送。
